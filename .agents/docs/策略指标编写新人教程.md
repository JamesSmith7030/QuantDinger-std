## 0. 先搞懂三个词

**K 线（bar）**：把一段时间的价格压缩成一根蜡烛。一根 K 线有 5 个数：
开盘价 `open`、最高价 `high`、最低价 `low`、收盘价 `close`、成交量 `volume`。

**指标**：对价格做数学计算得出的辅助线。比如"最近 10 天收盘价的平均值"就是
10 日均线。指标本身不赚钱，它只是帮你**描述行情**。

**策略**：一套明确的规则——**什么时候买、什么时候卖、买多少、亏多少就跑**。
策略 = 指标 + 进出场规则 + 风险控制。

一句话：**指标是眼睛，策略是大脑。**

## 1. 在 QuantDinger 里写策略是怎么回事

你不需要自己拉数据、画图、撮合成交——平台都包了。你只需要写一段 Python，
回答一个问题：

> **给你一张历史价格表，哪些行该买、哪些行该卖？**

平台会把价格表装进一个叫 `df` 的变量里（pandas DataFrame，可以理解成
一张 Excel 表，每行是一根 K 线）：

| time | open | high | low | close | volume |
|------|------|------|-----|-------|--------|
| 1月1日 | 100 | 105 | 99 | 104 | 5000 |
| 1月2日 | 104 | 108 | 103 | 107 | 6200 |
| ... | ... | ... | ... | ... | ... |

你的代码往这张表里**新加几列布尔值（True/False）**，标记"这一行要开多/平多/
开空/平空"。回测引擎读这几列，模拟下单，算出盈亏曲线。就这么简单。

> 你的代码跑在一个**沙盒**里：`df`、`pd`（pandas）、`np`（numpy）、`params`
> 这几个变量已经替你准备好了，直接用。不能联网、不能读写文件、不能 `eval`——
> 写了会被拒绝。

## 2. 第一个策略：双均线交叉（先看懂再动手）

最经典的入门策略，规则用人话说就是：

- 算一条"短均线"（最近 10 根 K 线的平均价，反应快）
- 算一条"长均线"（最近 30 根的平均价，反应慢）
- **短均线从下往上穿过长均线**（金叉）→ 行情转强 → 买入
- **短均线从上往下穿过长均线**（死叉）→ 行情转弱 → 卖出

完整代码（可以直接贴进指标 IDE 跑）：

```python
my_indicator_name = "我的第一个双均线策略"
my_indicator_description = "短均线上穿长均线买入，下穿卖出"

# signal_form: four_way
# exit_owner: engine
# flip_mode: R2

# @param fast_len int 10 短均线周期
# @param slow_len int 30 长均线周期

# @strategy stopLossPct 0.03
# @strategy takeProfitPct 0.06
# @strategy entryPct 0.25
# @strategy trailingEnabled false
# @strategy tradeDirection long

# ===== 第一步：固定开头，复制一份表，别改原始数据 =====
df = df.copy()

# ===== 第二步：读取参数（上面 @param 声明了，这里就要用 params.get 读）=====
fast_len = int(params.get('fast_len', 10))
slow_len = int(params.get('slow_len', 30))

# ===== 第三步：算指标 =====
# ewm(...).mean() 就是"指数移动平均线 EMA"，一行搞定
ema_fast = df['close'].ewm(span=fast_len, adjust=False).mean()
ema_slow = df['close'].ewm(span=slow_len, adjust=False).mean()

# ===== 第四步：写信号 =====
# "金叉" = 今天短线在长线上方，且昨天还在下方（shift(1) 就是"昨天的值"）
golden_cross = (ema_fast > ema_slow) & (ema_fast.shift(1) <= ema_slow.shift(1))
death_cross  = (ema_fast < ema_slow) & (ema_fast.shift(1) >= ema_slow.shift(1))

golden_cross = golden_cross.fillna(False).astype(bool)
death_cross  = death_cross.fillna(False).astype(bool)

# ===== 第五步：填四路执行列（平台标准，照抄这个结构）=====
df['open_long']   = golden_cross   # 金叉：开多
df['close_long']  = death_cross    # 死叉：平多
df['open_short']  = death_cross & False   # 本策略只做多，空头两列全 False
df['close_short'] = golden_cross & False

# ===== 第六步：画图输出（只影响图表显示，不影响成交）=====
buy_marks  = [df['low'].iloc[i] * 0.995 if golden_cross.iloc[i] else None for i in range(len(df))]
sell_marks = [df['high'].iloc[i] * 1.005 if death_cross.iloc[i] else None for i in range(len(df))]

output = {
    "name": my_indicator_name,
    "plots": [
        {"name": "EMA 10", "data": [None if pd.isna(x) else float(x) for x in ema_fast],
         "color": "#1890ff", "overlay": True, "type": "line"},
        {"name": "EMA 30", "data": [None if pd.isna(x) else float(x) for x in ema_slow],
         "color": "#faad14", "overlay": True, "type": "line"},
    ],
    "signals": [
        {"type": "buy",  "text": "买", "data": buy_marks,  "color": "#00E676"},
        {"type": "sell", "text": "卖", "data": sell_marks, "color": "#FF5252"},
    ],
}
```

**每一段都干了什么，再用人话过一遍：**

| 段落 | 干了什么 | 为什么 |
|------|----------|--------|
| `my_indicator_name/description` | 给策略起名字 | 平台列表里显示用 |
| `# signal_form / exit_owner / flip_mode` | 头部"契约声明" | 告诉引擎你用哪种信号格式、谁负责止盈止损（第 4 节细讲） |
| `# @param` | 声明可调参数 | 以后在界面上改参数不用改代码 |
| `# @strategy` | 默认风控配置 | 止损 3%、止盈 6%、每次用 25% 资金、只做多 |
| `df = df.copy()` | 复制表格 | 固定开头，防止污染原始数据 |
| 算 EMA → 写信号 | 策略核心 | 眼睛 + 大脑 |
| 四路执行列 | **真正决定下单的列** | 引擎只认这四列 |
| `output` | 图表展示 | 让你在 K 线图上看到均线和买卖点 |

## 3. 新人最容易栽的三个坑（务必看懂）

### 坑一：信号"连续触发"

错误写法：

```python
df['open_long'] = ema_fast > ema_slow   # ❌
```

短线在长线上方的**每一根 K 线**都是 True——趋势持续 50 根，就发 50 次买入信号。
你想表达的其实是"**刚刚**上穿的那一下"才买。

正确做法叫**边缘触发**——和昨天比，从 False 变 True 的那一根才算：

```python
raw = (ema_fast > ema_slow).fillna(False).astype(bool)
prev = raw.shift(1).fillna(False).astype(bool)   # 昨天的状态
df['open_long'] = raw & ~prev                    # ✅ 只在"刚变 True"那根触发
```

记住口诀：**条件刚成立时触发一次，不是成立期间一直触发。**

> 小陷阱：`shift(1)` 之后必须再 `.astype(bool)` 一次。布尔列经过 shift 会
> 变成"杂牌类型"（object），直接 `~` 取反在新版 pandas 里会得到 -1/-2 这种
> 整数，过滤悄悄失效——信号又变成每根都触发，而且不报错。

### 坑二：偷看未来（未来函数）

```python
df['open_long'] = df['close'].shift(-1) > df['close']   # ❌ shift(-1) 是"明天的价格"
```

用明天的价格决定今天买不买——回测里稳赚（因为你开了天眼），实盘必亏
（因为没人知道明天）。**任何 `shift(-1)` 都是作弊**，回测好得离谱时第一个查这个。

合法方向只有往回看：`shift(1)` 是昨天，`rolling(20)` 是最近 20 天。

### 坑三：止损写两遍，被平仓两次

止盈止损有两个人能管：

- **引擎管**（`# exit_owner: engine`）：你只写进场信号，
  `# @strategy stopLossPct 0.03` 这些配置由平台自动执行。**新人推荐**。
- **指标自己管**（`# exit_owner: indicator`）：你把"跌破止损线就卖"直接写进
  `close_long` 信号里，同时必须写 `# @strategy trailingEnabled false`。

**只能选一个**。两边都写窄止损，实盘会出现"引擎刚平完仓，你的信号又来平一次，
仓位是 0 被拒单"的灵异现场。

## 4. 那些头部注释到底什么意思（速查）

### `# @strategy`（默认风控，引擎读取）

| 写法 | 人话 |
|------|------|
| `stopLossPct 0.03` | 价格跌 3% 就止损（**0–1 小数**，0.03 = 3%） |
| `takeProfitPct 0.06` | 涨 6% 就止盈 |
| `entryPct 0.25` | 每次开仓用 25% 的钱（**注意 `1` 是 100% 不是 1%！**） |
| `trailingEnabled true` | 开启"移动止损"（盈利后止损线跟着价格上移） |
| `trailingStopPct 0.02` | 从最高点回撤 2% 就走 |
| `trailingActivationPct 0.04` | 盈利超 4% 后才启动移动止损 |
| `tradeDirection long` | 只做多（`short` 只做空，`both` 双向） |

**杠杆不许写在代码里**——它在平台界面上配置。

### 头部契约三连

```python
# signal_form: four_way    ← 我用四路信号列（新代码一律这个）
# exit_owner: engine       ← 止盈止损归引擎管（或 indicator = 归我的信号管）
# flip_mode: R2            ← 反手时同一根 K 先平后开（R1 = 下一根再开）
```

### 四路信号列（引擎唯一认的下单依据）

| 列 | 含义 |
|----|------|
| `df['open_long']` | 开多（买入做涨） |
| `df['close_long']` | 平多（卖出离场） |
| `df['open_short']` | 开空（做跌） |
| `df['close_short']` | 平空 |

四列**必须都存在**、都是布尔、长度和 `df` 一样。只做多的策略，空头两列填全 False 即可。

> 老代码里你会看到 `df['buy']` / `df['sell']` 两路写法——能看懂就行，
> **自己写新策略别用**，`both` 模式下它有"买入信号会顺手反手"的隐藏语义，新人容易翻车。

## 5. 回测是怎么成交的（不懂这个，回测结果会骗你）

平台的成交规则是固定的，记住一句话：

> **信号在 K 线收盘时确认，在下一根 K 线的开盘价成交。**

意思是：1 月 5 日收盘后金叉成立 → 系统在 1 月 6 日**开盘价**买入（还会扣手续费、
算滑点）。不是金叉那一瞬间就按当时价格买。

所以：

- 你画在图上的"止损线"≠ 系统一定按那个价格成交；
- 回测结果里"平空后立刻开多"是 `both` 模式的正常行为，不是 bug；
- 仓位大小由 `entryPct` 决定，不是你以为的"全仓"。

**判断回测靠不靠谱的土办法**：点开成交明细，随便挑 3 笔，手动对照 K 线图问自己
"如果我当时在场，真能在这个价格成交吗？"

## 6. 完整工作流：从想法到回测

```
想法（"金叉买死叉卖"）
   │
   ▼
① 写 IndicatorStrategy（照第 2 节模板改）
   │
   ▼
② 校验代码 ──不过──► 看报错改代码（最常见：四列没填全、长度不一致）
   │ 通过
   ▼
③ 跑回测（选标的、周期、时间段，strictMode 开着）
   │
   ▼
④ 看结果 ──不对劲──► 自检：连续触发？未来函数？双重止损？
   │ 满意
   ▼
⑤ 调参数（改 @param 默认值或界面扫参），定稿后把最终参数写回代码
   │
   ▼
⑥ 保存成策略 → 用"保存后的策略"再跑一次回测（这步最接近实盘）
```

具体怎么调 API / MCP 工具跑回测，看
[backtest-and-api.md](../skills/quantdinger-std/references/backtest-and-api.md)。
在平台界面操作的话：左侧 **指标 IDE** 写代码 → 右侧面板直接回测。

## 7. 什么时候需要"高级模式"（ScriptStrategy）

上面写的 IndicatorStrategy 是"填表式"：一次算完整张表的信号。它有个天然限制——
**不知道你现在拿着多少仓位**。

如果你的策略需要"看着持仓做决定"，比如：

- 浮盈超 5% 后，把止损移到成本价（保本单）
- 第一次买 30%，跌 2% 再补 30%（分批建仓）
- 止损后冷静 10 根 K 线不准再进（冷却期）

就要换 ScriptStrategy：写 `on_init(ctx)` 和 `on_bar(ctx, bar)` 两个函数，
每根 K 线收盘引擎喊你一次，你通过 `ctx.position` 看持仓、用 `ctx.buy()` /
`ctx.sell()` / `ctx.close_position()` 下单。

新人建议：**先把 IndicatorStrategy 玩熟**，确实碰到上面那类需求再升级。
ScriptStrategy 的 API 表在
[strategy-authoring.md 第 7 节](../skills/quantdinger-std/references/strategy-authoring.md)。

## 8. 报错急救表

| 报错/现象 | 多半是因为 | 怎么办 |
|-----------|-----------|--------|
| 校验不通过：缺函数 | ScriptStrategy 少写了 `on_init` 或 `on_bar` | 两个都写上，哪怕 `on_init` 只有一行 log |
| 图表渲染报错 | 某条 plot/signal 的 `data` 长度 ≠ K 线数量 | 所有数组都从 `df` 算，长度对齐 `len(df)` |
| 声明了参数没生效 | 写了 `# @param` 却把数字硬编码在代码里 | 用 `params.get('xxx', 默认值)` 读 |
| 回测好得不像话 | 99% 是未来函数 | 全文搜 `shift(-1)`，删掉重写 |
| 买卖点密密麻麻 | 信号连续触发 | 加边缘触发（第 3 节坑一） |
| 实盘日志 `invalid amount (0.0)` | 双重止损，仓位已被引擎平掉 | 重选 exit_owner（第 3 节坑三） |
| import 被拒绝 | 用了白名单外的库 | 只能用 numpy/pandas/math/json/datetime 等基础库 |
