### 1.1 网络与代理要求（国内环境必读）

**OKX 技能**（`okx ...` 命令）：CLI 内置 EnvHttpProxyAgent，自动读 `HTTP(S)_PROXY`，本机有 Clash（`127.0.0.1:7890`）即可直接用，无需额外设置。

**Binance Web3 技能**（query-token-info / query-token-audit / query-address-info / crypto-market-rank / trading-signal / meme-rush / binance-tokenized-securities-info）：底层是 `node scripts/cli.mjs` 裸 `fetch`，直连 `web3.binance.com` 在国内被墙。需两个条件：

1. **Clash 代理开启**（`127.0.0.1:7890`）。
2. **让 node 的 fetch 走代理**——Node 原生 fetch 默认不读 `HTTP_PROXY`，必须额外设 `NODE_USE_ENV_PROXY=1`：

```powershell
$env:NODE_USE_ENV_PROXY='1'; $env:HTTPS_PROXY='http://127.0.0.1:7890'; $env:HTTP_PROXY='http://127.0.0.1:7890'
```

已用 `setx NODE_USE_ENV_PROXY 1` 持久化，**未来新开的会话自动生效**（当前已运行的会话因父进程环境已固定，仍需上面那行内联补设）。

**已修复的两处 Windows 适配 bug**（改在 `~/.claude/skills/query-token-info/scripts/cli.mjs`，其余 Binance Web3 技能若同样静默无输出，按同法修）：
- 直执行守卫 `import.meta.url === \`file://${process.argv[1]}\`` 在 Windows 反斜杠路径下永不匹配 → 命令静默无输出。已改为 `pathToFileURL(process.argv[1]).href` 比较。
- 配合上面的 `NODE_USE_ENV_PROXY` 解决"Network request failed"。

**Bitget 技能**：`bitget` 走 bgc CLI；5 个分析技能（technical-analysis 等）走本地 Python(pandas/numpy) + `api.bitget.com`。免凭证类只需 pandas/numpy（`pip install pandas numpy`）。

### 1.2 ⚠️ 网络方案随环境变化（2026-06-15 更新）

代理方式取决于当前网络，**两种互斥**，用错会卡住：

| 网络场景 | 做法 |
|----------|------|
| **本地 Clash（127.0.0.1:7890）** | Binance Web3 类需 `$env:NODE_USE_ENV_PROXY='1'; $env:HTTPS_PROXY='http://127.0.0.1:7890'`；OKX CLI 自动读代理 |
| **路由器透明代理（网关级）** ✅当前 | **清空所有代理变量直连**：`$env:HTTP_PROXY=''; $env:HTTPS_PROXY=''; $env:ALL_PROXY=''; $env:NODE_USE_ENV_PROXY=''`；并 `git config --global --unset http(s).proxy`。浏览器/直连即通，**设了 7890 反而失败**（端口未监听） |

> 判断方法：`Test-NetConnection 127.0.0.1 -Port 7890` 通=本地 Clash 模式；不通但 `Invoke-WebRequest https://github.com` 直连 200=路由器透明代理模式。安装/运行任何交易所技能前先确认当前是哪种。

### 1.3 🧭 多所技能路由规则（重叠/冲突的处理，2026-06-15 定）

三所技能存在能力重叠（详见 §4 测试表 1.2.7）。**账户/交易类靠交易所名+独立凭证天然隔离**；**分析/行情类高度冗余**，按下列规则路由，避免选到次优技能或被跨所数值差异误导：

**规则①｜指明交易所 = 终结歧义（最高优先）**
用户说"用 **OKX** 看…/用 **Bitget** 看…/查 **Binance** 余额"，直接路由到该所对应技能，不再择优。下单/账户类**必须**走指明的所。

**规则②｜不指明时，按能力择优**（实测得出的最优数据源）：

| 分析能力 | 首选 | 原因 |
|----------|------|------|
| 周期估值（AHR999/彩虹/抄底区） | **OKX**（okx-cex-market） | 原生指标，Bitget/Binance 都没有 |
| 资金费率 | **OKX**（okx-cex-market） | Bitget datahub 不暴露 funding |
| 宏观（利率/收益率曲线/CPI/就业） | **Bitget**（macro-analyst·datahub FRED） | FRED 官方全套，OKX/Binance 均无 |
| 新闻简报 | **Bitget**（news-briefing·44 源 RSS） | 时效强、多空双视角 |
| 情绪/恐贪/多空分层 | **Bitget**（sentiment-analyst） | 恐贪指数+散户/大户拆分+OI 趋势 |
| 纯技术指标（RSI/MACD/BOLL） | **kline-indicator**(OKX) 或 **technical-analysis**(Bitget) | 二选一，结果应吻合 |
| 单币现价/K线 | OKX（免凭证直连最省事） | 国内直连无坑 |
| 股票/股票代币 | **datahub global_assets + technical-analysis 引擎** | 见 crypto-analysis-report 股票分支 |

**规则③｜跨所数值差异 = 交叉验证信号，不是 bug**
同一指标不同所数值不同（如多空比 OKX 1.02 vs Bitget 1.43，因交易所样本+口径不同）属正常。**差异大本身是信号**（如散户/大户背离）；需要权威值时多所并查取共识。

**规则④｜下单永远单所，绝不跨所路由交易**
行情/分析可跨所聚合，但任何下单/撤单/转账/仓位操作只在用户明确指定的单一交易所执行，严禁跨所混合。

> 落地：综合研判（如生成报告）默认 **Bitget 跑宏观/新闻/情绪 + OKX 补周期估值与费率**，二者并用最优。
