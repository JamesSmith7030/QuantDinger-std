# 修改后 SOL 与 BTC 策略代码审查

## 1. 文档信息

- **任务类型**：只读代码审查
- **审查对象**：QuantDinger IndicatorStrategy
- **优先级**：高
- **策略代码修改**：禁止

## 2. 背景

两份策略经过修改后，需要重新审查其代码正确性、QuantDinger 策略契约符合性、
实盘执行风险，以及修改内容是否正确处理此前发现的风险控制和交易所下单问题。

## 3. 目标

1. 分别审查 SOL 双均线做多策略与 BTC PowerTower 双向策略。
2. 识别会导致错误信号、无法平仓、风险失控、回测与实盘不一致或订单被拒绝的问题。
3. 按 P1、P2、P3 严重程度输出已验证的审查发现。
4. 明确区分策略代码缺陷、策略参数风险与交易所账户或订单限制。

## 4. 审查范围

### 4.1 策略 A

`indicator_simulated_trading/v1.0.1(SOL4H做多+355.19)-双均线策略.py`

### 4.2 策略 B

`indicator_simulated_trading/v1.0.6 self(双向+31.83) PowerTower 策略-BTC.py`

## 5. 审查要求

### 5.1 策略契约

- 检查两路或四路信号与 `tradeDirection` 的执行语义。
- 检查是否声明 `signal_form`、`exit_owner` 和必要的策略默认值。
- 检查信号列是否为布尔类型且长度与行情数据一致。
- 检查是否存在 `shift(-1)` 等未来函数。

### 5.2 信号逻辑

- 检查开仓、平仓、反手逻辑是否符合策略描述。
- 检查 pandas 3.x 环境下边缘触发是否有效。
- 检查同一根 K 线是否可能产生冲突信号。
- 检查前导 NaN 是否会污染信号或图表数据。

### 5.3 参数与风险控制

- 检查 `@param` 默认值与 `params.get()` 回退值是否一致。
- 检查 `entryPct`、止损、止盈和跟踪止损配置。
- 检查是否存在零止损裸跑、双重退出或异常风险暴露。
- 评估开仓比例对交易所余额和最小下单量的影响。

### 5.4 验证

- 查看当前策略文件及其 Git 修改内容。
- 运行适用的语法检查和轻量策略验证器。
- 每项 P1/P2 发现必须由代码或验证结果支持。
- 审查结论必须提供准确文件和行号。

## 6. 严重程度定义

- **P1**：可能导致错误交易、风险失控、无法退出、实盘行为严重偏离预期。
- **P2**：可能导致部分场景失效、配置不一致、交易被拒绝或明显回测偏差。
- **P3**：可维护性、描述准确性、兼容性或低概率边界问题。

## 7. 验收标准

- [x] 两份策略均得到独立审查结论。
- [x] 所有 P1/P2 发现均经过实际代码验证。
- [x] 审查结果按严重程度排序并标注文件和行号。
- [x] 明确说明已通过的关键检查项。
- [x] 报告剩余测试缺口和残余风险。
- [x] 未修改任何策略源代码。

## 8. 非目标

- 不修复或重写策略。
- 不改变策略参数、交易方向或交易逻辑。
- 不重新优化参数或比较策略收益。
- 不修改交易所、账户、资金、杠杆或实盘配置。
- 不执行实盘交易或下单。
